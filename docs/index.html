01

Article one

Three traits, and nothing about any one registry

A registry is a place a service writes its address and a caller reads it back. That is all the contract fixes. What the registry does with a lapsed lease, how a watcher learns of a change, whether the store is a process, a cluster or a key-value server — none of it reaches the caller.

i

Registrar

register(service, endpoint, ttl) → Lease
renew(lease)
deregister(lease)

An address is known for its lease and no longer. Renewing extends it; a lease the registry has let go raises Refused::Expired.

ii

Discovery

resolve(service) → [Endpoint]
watch(service) → &Watcher

One answer now, or a stream of answers. A service nobody registered has no endpoints; that is not an error.

iii

Watcher

next() → Update
close()

Whole snapshots, never events. Reconnecting and recovering from a compacted history are the backend's business, so what comes out is what is true now.

02

Article two

A lease, and who keeps it

An endpoint is alive because something keeps saying so. hold renews at a third of the lease and registers again when the registry has forgotten it. View follows a service in one task and hands the latest list to whoever is on the request path, without a round trip.

Both are written once, against the traits, so a backend gets them by implementing six methods: 

async fn serve(registry : &@moonsd.Registrar) -> Unit {
  let endpoint = @moonsd.Endpoint::new("10.0.0.1", 12000, metadata=Map([("zone", "a")]))
  @async.with_task_group(group => {
    group.spawn_bg(() => @moonsd.hold(registry, "greeter", endpoint, ttl=15_000))
    // serve here; leaving the group cancels hold, which deregisters
  })
}

Article four

Held to the same behaviour

A backend is not finished when it compiles. conformance.check runs every behaviour the contract promises against one registrar and one discovery: the fields that survive a round trip, the lease that lapses, the watcher that hears a change and then hears the service empty. Each client's suite runs it against the real server, in CI.
