pub(open) trait Discovery {
  async fn resolve(Self, String) -> Array[Endpoint]
  async fn watch(Self, String) -> &Watcher
}

Where a service's callers find its instances.

resolve answers once, with no endpoints for a service nobody registered. watch follows one service: its watcher's first next gives the service as it stands, and each later one waits for a change. Implement these two and View works for the backend.

pub(open) trait Registrar {
  async fn register(Self, String, Endpoint, Int32) -> Lease
  async fn renew(Self, Lease) -> Unit
  async fn deregister(Self, Lease) -> Unit
}

Where a service's instances announce themselves.

register makes endpoint known under service for ttl milliseconds; renew extends that, and raises Expired once the backend has let it go; deregister removes it at once, and is harmless on a lease already gone. Implement these three and hold works for the backend.

pub(open) trait Watcher {
  async fn next(Self) -> Update
  fn close(Self) -> Unit
}

One service followed. next gives whole snapshots rather than events, so losing a connection costs an implementation a reconnect and a caller nothing: reconnecting, and recovering from a compacted history, are the implementation's business, and what comes out is always what is true now. next raises when the watcher cannot go on; close ends it.

Keep endpoint registered under service until the task is cancelled, then remove it.

It renews every renew_after(ttl) milliseconds, a third of the lease. The first register failing is raised: nothing has been announced, and the caller should hear. After that a failure is a backend that went away, which is no reason to stop serving: it goes to report and the next round registers again, so the endpoint comes back with the backend.

How long hold waits between two renewals of a lease of ttl milliseconds: a third, the interval a lease needs to survive two lost renewals. Never zero, so a tiny ttl does not turn the loop into a spin.

Run every behaviour the contract promises against one backend, under service, which must be unused; everything it registers it removes. A backend's own test suite calls this against a real server, so all backends are held to the same behaviour.

pub async fn keep_alive(@moonconsul.Session, String, Int32) -> Unit

Keep session id alive until the task is cancelled, renewing at half of ttl milliseconds and following the TTL the agent answers with.

A failed renewal is tried again each second until ttl has passed since the last good one, and then raised. A session the agent no longer knows raises NotFound.

Follow kind until the task is cancelled, calling handler with the index and the value each time the value changes. The first value is reported too, and an absent one reads as Null.
